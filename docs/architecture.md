# OrderPilot 框架与已确认范围

## 已确认业务范围

单企业、多店铺、单仓库；订单允许多个 SKU，整单履约，不拆单、不合单、不分批发货。
ERP 仅接收已支付订单；外部平台、支付、物流及业务样例可以模拟，内部业务功能应实际实现。
最终主线为：订单同步 → 审核 → 整单占用库存 → 拣货出库 → 发货签收。
异常处理围绕缺货、出库单下发失败、物流状态不同步展开，Agent 调用受控业务工具调查并提供证据，关键操作人工确认。
这些业务流程是后续开发范围，不是当前骨架已经实现的功能。

## 工程结构

Maven 父工程 `com.orderpilot:orderpilot:0.1.0-SNAPSHOT`，统一 Java 17、Spring Boot 3.5.13、Spring AI 1.1.8。
八个业务 jar：system、channel、product、oms、inventory、wms、workorder、agent。
boot 是唯一启动模块，依赖八个业务模块。当前业务模块之间没有依赖，具体协作接口在业务实现时设计。
系统接口位于 system，启动入口、运行配置与跨模块启动验证位于 boot。
包根统一为 `com.orderpilot`；模块后缀对应业务包名。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| system | 用户、角色、权限、审计；当前只有框架信息接口 |
| channel | 平台与店铺、SKU 映射、订单同步与重试 |
| product | SPU、SKU、规格及内部商品资料 |
| oms | 订单审核、取消、状态流转与履约协调 |
| inventory | 余额、占用、释放、扣减与流水 |
| wms | 仓库、入库、拣货、出库、发货与物流跟踪 |
| workorder | 异常登记、工单分派、处理与复核关闭 |
| agent | 智能排查、工具执行、证据记录与评测 |

库存余额只由 inventory 修改，仓储单据只由 wms 修改，订单状态只由 oms 修改。
Agent 调用业务接口，不直接改业务表。不要跨模块直接调用 Mapper。
模拟平台属于渠道接入的适配实现，不另建商城。

## 当前运行方式

`local` 是默认 profile，排除 JDBC 数据源自动配置；无需数据库、Redis、MQ 或模型密钥即可检查骨架启动。
`mysql` profile 使用环境变量配置 MySQL，数据库名默认为 `orderpilot`；健康检查将检查数据源。
两种 profile 应单独使用，不要同时启用 local 与 mysql。
数据库初始化 SQL 必须手动执行，不自动建表、删表或导入数据。
Spring AI 仅统一依赖版本，并在 agent 中引入 ChatClient 库；未注册模型 bean，未自动发起模型请求。

## 当前边界

已完成后端工程骨架、启动入口、健康检查、框架信息接口和 HTTP 错误响应基础配置。
登录权限、订单业务、数据库表、ORM、前端页面、真实模型连接和 Agent 执行流程尚未实现。
当前默认监听 127.0.0.1。数据库 profile 的真实连通性需在配置有效数据库账号后验证。
